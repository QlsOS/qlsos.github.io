QlsOS на реальном железе: чек-лист

Пройдите его на каждой новой машине и запишите результат в таблицу в конце. Первая машина: ASUS K50IJ, 2026-10-31 (подробности: ARCHITECTURE.md, раздел 27.4).

0. Перед началом

  • [ ] У машины legacy BIOS или UEFI с CSM / «legacy boot». QlsOS грузится через BIOS (int 0x13); чистая загрузка UEFI не поддерживается.
  • [ ] Сделайте резервную копию всего ценного на машине. QlsOS не пишет на диск, который не видит, но не рассчитывайте на это для данных, которые нельзя потерять.
  • [ ] USB-флешка, которая вам не нужна (она будет перезаписана целиком).
  • [ ] У машины встроенная или эмулирующая PS/2 клавиатура (USB-клавиатура без эмуляции PS/2 в BIOS пока не даёт шеллу ввода).

1. Сделайте флешку

  1. make usb.img (Linux / WSL).
  2. Запишите образ:
    • Linux: make usb-write DEV=/dev/sdX (отказывается работать с разделами, смонтированными и несъёмными дисками и проверяет запись обратным чтением);
    • Windows: Rufus с выбором usb.img как метода загрузки (режим образа / «DD Image») или Win32DiskImager. WSL1 не видит USB-устройства.
  3. Не позволяйте Windows форматировать флешку после этого (она может предложить; файловой системы на флешке нет, это нормально).

2. Загрузка

  1. Вставьте флешку, включите машину и откройте меню загрузки (Esc, F12, F8 или F9 — зависит от производителя; ноутбуки ASUS: Esc).
  2. Выберите флешку: сначала пункт USB-HDD, если не грузится — USB-FDD.
  3. Если флешки нет в меню: настройка BIOS (F2 / Del) -> Boot: включите USB boot / legacy boot, выключите Fast Boot / Boot Booster.

Что вы должны увидеть: загрузчик печатает kernel crc ok, затем журнал ядра, баннер QlsOS v0.1.0 и приглашение.

3. Команды, в таком порядке

Безопасны на любой машине (только читают или работают в RAM):

#КомандаЧто проверить
1helpпоявляется список тем; клавиатура печатает, Backspace и стрелки работают
2framesпечатает physical frames: N free / M total; 16384 всего — потолок PMM (64 МБ), а не память машины
3lspciPCI-устройства машины; запишите SATA-контроллер (класс 0106, prog_if 01 = AHCI)
4uptime, dateтаймер тикает (100 раз в секунду); дата берётся из RTC
5ps, capsперечислены задачи и их handles
6mouse, затем подвигайте тачпад / мышьзначения меняются (PS/2)
7exec helloпрограмма выполняется в ring 3 и завершается с кодом 0
8shзапускается шелл ring 3; внутри help, echo hi, run hello; exit возвращает назад
9kbd status, consoleсообщается о обоих сервисах
10benchзавершается и пишет baseline.txt (cat baseline.txt)
11diskdump 0только чтение. no IDE disk found = ядро не видит диск (режим AHCI); тогда активна ramfs, и файлы не переживут перезагрузку
12mountкакая файловая система активна (ramfs или qlsfs)
13faulttestкаждый вид сбоя убивает только одну задачу; нет FAIL
14rebootмашина перезапускается (она загрузит обычную систему, если флешка не первая в порядке загрузки: это ожидаемо)
15shutdownмашина выключается

Не запускайте на машине, диск которой вам дорог: format (стирает диск, если ядро его видит) и disktest (пишет тестовый сектор). Ядро форматирует диск при загрузке, только если его первые 64 сектора (32 KiB) целиком нулевые, поэтому диск с системой сама загрузка никогда не трогает.

5. Известные ограничения на реальных машинах

  • Менеджер памяти использует только первые 64 МБ RAM.
  • Драйвера AHCI пока нет: SATA-диск в режиме AHCI невидим; файлы сессии живут в RAM. (В некоторых BIOS есть режим IDE / совместимости для SATA; с ним старый драйвер может увидеть диск.)
  • USB-клавиатура без эмуляции PS/2 в BIOS не поддерживается; ввода через последовательный порт пока нет.
  • На первой машине dmesg напечатал пустой журнал (в QEMU там события ядра): пока не разобрано.
